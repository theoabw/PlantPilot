From scan to service.

A 3D scan shows a plant room but knows nothing about it. PlantPilot finds the equipment, plans a robot's route to the faulty pump and opens a cited diagnosis on arrival. All of it runs offline.

One chain, one file at a time

Every stage writes something you can open and check.

The pipeline is plain geometry and joins, so a result can be traced to the file and the rule that produced it.

  1. scene.npz

    Read the capture

    Validates the PLY, keeps the readable gaussians and works out which way is up from the room itself. The first delivered file was truncated, so this stage keeps only the part that can be trusted.

    502,483 of 1,506,136rows readable in the truncated file, reported rather than guessed

  2. objects.json

    Find the objects

    Removes the floor, ceiling and walls, then clusters what is left and fits a 3D box to each object. A gate on horizontal planes stops a floor plane slicing a machine in half.

    100 to 14 percentremoved from a machine's cross-section once the gate is on, with the floor still removed at 90 percent

  3. mapped.json

    Propose what they are

    Assigns the 30 workbook records one-to-one using class and size, behind two hard gates. Every record says proposed or unresolved, and a label the geometry cannot support becomes plain object.

    25 labelschanged to object because no pipework or support backed them up

  4. route.json

    Plan the route

    Builds a 10 cm occupancy grid from four layers: observed floor, walls, object footprints and overhead structure. A* then plans to a stand-off point beside P-005, so the robot cannot leave the room it actually saw.

    1.91 m, 0.32 m clearthe planned route on the complete capture and its tightest clearance

  5. diagnosis.json

    Explain the fault

    Joins P-005's state, telemetry, alarms, data-quality cases and documents. Every claim cites an evidence id, and the card ends with the next safe check and the document behind it.

    5 claims, 3 causeseach claim cited, each alternative cause given a verdict from a named threshold

Grounded, not generated

It says why, and what it ruled out.

The reasoning comes from computed changes in the telemetry and fixed thresholds, not a model. The same pack gives the same answer every time.

144telemetry rows 34alarms 9data-quality cases 2documents
  • THE READING Fouling on P-005

    Health 44 at high urgency. Next safe check: inspect hydraulic path, from DOC-FIELD-SAFETY.

  • RULED OUT Suction restriction

    Weighed as an alternative cause and given a verdict on the card.

  • RULED OUT A drifting flow sensor

    Weighed against the motor current, because a sensor that drifts does not load the motor.

  • P-005's records are synthetic data from the supplied Valmet builder pack, not measurements of a physical machine.

The honest part

What is real, what is proposed and what is synthetic.

The viewer keeps these apart on screen too, so a pack condition never reads as a measurement of the machine it was assigned to.

PartStatusWhat that means
The captureRealA supplied scan. Units are treated as metres, and no door-height scale check was done.
3D frames and routeRealComputed from the capture. 122 smaller clusters fall outside the 150-object cap, which is why the route also uses the floor, wall and overhead layers.
Equipment mappingProposedA match score, not a calibrated probability. The pack has no measured positions, so P-005 on OBJ-037 is a proposal, not an identification.
Class labelsProposedGeometric proposals. 8 objects are named by multi-view fusion, and SAM 3 text prompts were tried and not used for placing assets.
Telemetry and alarmsSyntheticSupplied synthetic Valmet data, labelled as a scenario in the viewer.
The robotSimulatedA viewer marker following the planned path at 0.5 m/s, not a physics simulation.

Run it

One command, on one machine.

The captures and workbook are supplied separately, so put them in data/supplied/ first. The room view needs a browser with WebGL2.

Python 3.12+ with uv, Node 20+ with pnpm. Built with three.js, Spark, React and FastAPI.

# from a fresh clone
uv sync
cd app/web && pnpm install && cd ../..

# build the artifacts and serve the room view
make demo

# open http://127.0.0.1:8000
