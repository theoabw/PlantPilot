From scan to service.

A 3D scan shows a plant room but knows nothing about it. PlantPilot finds the equipment, plans a robot's route to the faulty pump and opens a cited diagnosis on arrival, all offline.

Run the demo See how it works

Frame

Find what is actually in the room.

Planes come out first, then what is left is clustered and boxed. Each object keeps a class proposal and the reason behind it, and a label the geometry cannot support stays a plain object.

The chain

Every stage leaves a file you can check.

Plain geometry and joins, so any result can be traced to the file and the rule that produced it.

  1. scene.npz

    Read the capture

    Validates the PLY and works out which way is up from the room itself. The first delivered file was truncated, so this stage keeps only the part that can be trusted.

    502,483 of 1,506,136 rows readable in that file, reported rather than guessed

  2. objects.json

    Find the objects

    Removes the floor, ceiling and walls, clusters the rest and fits a 3D box to each object. A gate on horizontal planes stops a floor plane slicing a machine in half.

    100 to 14 percent removed from a machine's cross-section with the gate on, and the floor still at 90 percent

  3. mapped.json

    Propose what they are

    Assigns the 30 workbook records one-to-one by class and size, behind two hard gates. Every record says proposed or unresolved.

    25 labels changed to object because no pipework or support backed them up

  4. route.json

    Plan the route

    Builds the grid from four layers: observed floor, walls, object footprints and overhead structure. A* then plans to a stand-off point beside P-005.

    1.91 m, 0.32 m clear the planned route on the complete capture and its tightest clearance

  5. diagnosis.json

    Explain the fault

    Joins P-005's state, telemetry, alarms, data-quality cases and documents. Every claim cites an evidence id.

    5 claims, 3 causes each claim cited, each cause given a verdict from a named threshold

Grounded, not generated

The honest part

What is real, what is proposed and what is synthetic.

The viewer keeps these apart on screen too, so a pack condition never reads as a measurement of the machine it was assigned to.

Real

The capture
A supplied scan. Units are treated as metres, and no door-height scale check was done.
3D frames and route
Computed from the capture. 122 smaller clusters fall outside the 150-object cap, which is why the route also uses the floor, wall and overhead layers.

Proposed

Equipment mapping
A match score, not a calibrated probability. The pack has no measured positions, so P-005 on OBJ-037 is a proposal, not an identification.
Class labels
Geometric proposals. 8 objects are named by multi-view fusion, and SAM 3 text prompts were tried and not used for placing assets.

Synthetic

Telemetry and alarms
Supplied synthetic Valmet data, labelled as a scenario in the viewer.
The robot
A viewer marker following the planned path at 0.5 m/s, not a physics simulation.

Run it

One command, on one machine.

The captures and workbook are supplied separately, so put them in data/supplied/ first. The room view needs a browser with WebGL2.

Python 3.12+ with uv, Node 20+ with pnpm. Built with three.js, Spark, React and FastAPI.

from a fresh clone
uv sync
cd app/web && pnpm install && cd ../..
make demo
# then open http://127.0.0.1:8000
